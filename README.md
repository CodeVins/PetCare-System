# PetCare System

반려동물 케어 통합 플랫폼 — 병원 검색·예약, 반려동물 프로필/건강 관리, 실시간 알림, 1:1 채팅, 리뷰, 관리자 도구까지 제공하는 풀스택 포트폴리오 프로젝트입니다. 백엔드(Spring Boot)와 프론트엔드(React)를 한 저장소에서 함께 개발했습니다.

> 혼자 설계부터 구현까지 진행한 개인 포트폴리오 프로젝트이며, 실서비스가 아닌 학습/데모 목적입니다.

## 구조

모노레포로 구성되어 있으며, `main`/`backend`/`frontend` 세 브랜치가 저장소 전체(백엔드+프론트엔드)를 함께 스냅샷합니다.

```
petcare-project
├── backend   # Spring Boot REST API
│   └── CLAUDE.md   # 백엔드 아키텍처/도메인/컨벤션 상세 문서
└── frontend  # React (Vite) SPA
    ├── CLAUDE.md      # 개요/스택/컨벤션
    ├── PROGRESS.md    # 날짜별 상세 변경 이력
    ├── API_MAP.md     # 엔드포인트 ↔ 화면 매핑
    └── src/api/CLAUDE.md  # axios 레이어 컨벤션
```

## 기술 스택

**Backend**
- Java 21, Spring Boot 3.x, Gradle
- Spring Data JPA + Querydsl (동적 쿼리: 병원 검색/필터, 관리자 통계)
- Spring Security + JWT (Access Token + Refresh Token, stateless)
- MySQL (로컬 개발은 Docker)
- Server-Sent Events (실시간 알림/채팅 알림)
- springdoc-openapi (Swagger UI)
- JUnit 5 기반 통합 테스트 (H2 인메모리 DB)

**Frontend**
- React 19 (Vite, JavaScript)
- React Router v7 (SPA 라우팅, 역할 기반 보호 라우트)
- Axios (요청/응답 인터셉터로 토큰 자동 첨부 및 자동 재발급)
- Tailwind CSS v4 (유틸리티 기반 스타일링, 커스텀 디자인 토큰)
- Motion(舊 Framer Motion) — 스크롤 인터랙션/엔트런스 애니메이션
- Phosphor Icons
- Context API (전역 인증/알림 상태 — 규모상 Redux/Zustand 미사용)

## 핵심 설계

### 인증 & 세션
- JWT 기반 Stateless 인증. Access Token(1시간) + Refresh Token(14일, opaque random string) 발급.
- Refresh Token은 유저당 1개만 유지(멀티 디바이스 미지원), 재발급 시마다 회전(rotate)하여 재사용 공격 방지.
- 프론트 axios 인터셉터가 401 응답을 감지하면 자동으로 재발급을 시도하고, 동시에 여러 요청이 401을 받아도 재발급 요청은 1번만 보내도록 중복 제거(single in-flight promise 공유) 처리.
- 이메일 변경 시 JWT subject(=이메일)가 바뀌므로 기존 토큰이 즉시 무효화됨 — 프론트에서 자동 로그아웃 처리.
- 계정 정지(suspend) 기능은 로그인 시점에만 체크되는 구조로, 이미 발급된 Access Token은 최대 1시간 뒤 자연 만료(알려진 한계로 별도 명시).

### 역할(Role) 기반 접근 제어
- `USER` / `HOSPITAL_OWNER` / `ADMIN` 세 가지 역할.
- 신규 가입은 전부 `USER`로 생성되며, 공개된 관리자 가입 경로는 없음. 최초 관리자 계정은 서버 기동 시 환경변수 기반으로 자동 부트스트랩되고, 이후 추가 관리자는 기존 관리자가 승격.
- 병원 소유자(`HOSPITAL_OWNER`)는 관리자가 병원-유저를 연결해 지정하며, 지정 시 대상 유저가 자동으로 승격됨. 컨트롤러 레벨의 role 체크 + 서비스 레벨의 "내가 관리하는 병원이 맞는가" 재검증을 이중으로 적용.
- 프론트는 `PrivateRoute` / `OwnerRoute` / `AdminRoute`로 역할별 라우트 가드 구현.

### 동시성 제어
- 병원 예약 슬롯(`Slot`)에 낙관적 락(`@Version`)을 적용해 동시 예약 요청 시 한 건만 성공하도록 보장 (통합 테스트로 검증).
- 예약은 생성 즉시 확정되지 않고 `PENDING` 상태로 생성되며, 병원/관리자가 확정(`CONFIRMED`) 또는 거절(`REJECTED`)하는 승인 플로우로 설계.

### 실시간 기능 (SSE)
- WebSocket 대신 Server-Sent Events 채택 — 서버→클라이언트 단방향 알림만 필요한 요구사항에 더 간단한 구조로 판단.
- 브라우저 `EventSource`가 커스텀 헤더를 지원하지 않는 제약 때문에, 이 엔드포인트에 한해 쿼리 파라미터로 JWT를 전달하는 예외 인증 경로를 별도로 허용.
- 실시간 1:1 채팅은 별도 SSE 채널을 새로 만들지 않고 기존 알림 채널을 재사용 — 메시지 수신 시 "새 메시지 알림"만 SSE로 보내고, 프론트가 알림을 받으면 메시지 목록을 다시 조회하는 notify-then-refetch 패턴으로 범위를 좁게 유지.

### 데이터 조회 최적화
- 병원 검색은 Querydsl로 리뷰 평점 집계 + 키워드/평점/거리(Haversine 공식) 필터 + 정렬을 쿼리 하나로 처리.
- 대부분의 목록 API는 `Pageable` 기반 페이지네이션(`{content, page, size, totalElements, totalPages}` 공통 포맷)을 따르되, 성격상 페이지네이션이 맞지 않는 소수 엔드포인트(거리 기반 검색, 관리자 리포트, 개인용 D-day 목록)는 의도적으로 예외 처리.

## 기능

### 인증 / 계정
- 회원가입, 로그인/로그아웃, Access/Refresh Token 재발급
- 비밀번호 찾기(이메일 요청 → 토큰 기반 재설정, 30분 유효 1회용) — 실제 메일 발송 대신 서버 로그로 대체된 데모 구현
- 내 정보 조회/수정, 비밀번호 변경
- 관리자에 의한 계정 정지/활성화

### 반려동물 관리
- 반려동물 CRUD (이름/종/품종/생년월일/크기/사진)
- 사진 업로드(용량·확장자 검증, 서버 UUID 파일명으로 경로 조작 방지)
- 다중 보호자(가족 공유) 기능 — 최초 등록자와 공동 보호자가 일상 관리 권한(프로필/건강기록/예약/사진)을 동등하게 공유하되, 보호자 초대·퇴출과 반려동물 삭제는 최초 등록자만 가능하도록 설계
- 건강 기록(체중/예방접종/진료/산책/식사/배변/자가문진) CRUD, 체중 변화 그래프
- 예방접종 D-day 알림용 다음 접종 예정일 입력
- 사료 급여량 계산기(RER/DER 계산, 활동량별 계수 적용)
- 비대면 건강 자가문진(8개 고정 문항 → 저위험/중위험/고위험 판정, 통계 데이터 부재를 사용자에게 투명하게 안내하는 disclaimer 포함)

### 병원
- 병원 목록/검색 (키워드, 최소 평점, 거리 기반, 24시간 운영 여부, 주차 가능 여부 필터 + 정렬)
- 병원 상세(운영시간/진료과목/평균 진료비/사진), 병원 정보 등록·수정(관리자/소유자)
- 병원 사진 업로드
- 예약 가능 시간(슬롯) 조회/등록
- 즐겨찾기(찜) — 찜한 병원에 새 슬롯이 열리면 자동 알림
- 리뷰 작성/조회 (실제 방문 이력이 있는 유저만 작성 가능), 리뷰 신고, 병원측 답글
- 관리자 리뷰 모더레이션(숨김/해제)

### 예약
- 예약 생성 → 대기(`PENDING`) → 병원/관리자 확정 또는 거절
- 예약 취소, 노쇼(No-show) 처리
- 예약이 마감된 슬롯에 대한 대기자 명단(Waitlist) 등록 — 슬롯이 다시 열리면 대기 1순위에게 선착순 알림

### 알림
- 알림 목록, 읽음 처리, 안읽은 개수 뱃지
- 실시간 알림 수신(SSE)
- 알림 카테고리(예약/접종/찜한병원/채팅/대기자명단)별 수신 on/off 설정
- 예방접종 예정일 및 예약 전날 자동 리마인더(스케줄러)

### 채팅
- 고객-병원 1:1 채팅방 생성/조회, 메시지 송수신
- 새 메시지 실시간 알림(SSE) → 열려 있는 채팅방이면 자동 재조회

### 관리자
- 대시보드: 유저 관리(역할 변경, 정지/활성화), 병원 등록, 병원 소유자 지정
- 예약 대기열 관리(확정/거절/노쇼 처리)
- 통계(전체/병원별 예약·리뷰·노쇼 집계)
- 리마인더 수동 실행(테스트/데모용)
- 리뷰 신고 목록 확인 및 모더레이션

### 프론트엔드 UX
- 반응형 레이아웃(데스크톱 가로 네비게이션 / 모바일 하단 탭바), 모바일 퍼스트 CSS
- 일관된 디자인 시스템(단일 teal 액센트, stone 중성 배경, 버튼=pill/카드=rounded-2xl/입력창=rounded-lg 형태 고정)
- 스크롤 진입 애니메이션, 버튼 프레스/호버 피드백, 브랜드 톤 그림자
- 커스텀 404 페이지, 스킵 링크 등 접근성/완성도 디테일

## 실행 방법

### 사전 준비
- Java 21, Node.js, Docker(또는 로컬 MySQL)

### Backend

```bash
cd backend

# MySQL 준비 (예시 — 실제 계정/비밀번호는 직접 지정)
docker run --name petcare-mysql \
  -e MYSQL_ROOT_PASSWORD=<root_password> \
  -e MYSQL_DATABASE=petcare \
  -e MYSQL_USER=<db_user> \
  -e MYSQL_PASSWORD=<db_password> \
  -p 3306:3306 -d mysql:8.0

# backend/.env 파일 생성 후 아래 값 채우기
# DB_USERNAME=<db_user>
# DB_PASSWORD=<db_password>
# JWT_SECRET=<임의의 긴 랜덤 문자열>
# ADMIN_EMAIL=<최초 관리자로 사용할 이메일>
# ADMIN_PASSWORD=<최초 관리자 비밀번호>

./gradlew bootRun
```

서버 기동 시 `.env`의 `ADMIN_EMAIL`/`ADMIN_PASSWORD`로 최초 관리자 계정이 자동 생성됩니다.

### Frontend

```bash
cd frontend
npm install
npm run dev
```

기본적으로 `http://localhost:5173`에서 실행되며, 백엔드 CORS는 이 포트만 허용합니다. 다른 포트를 쓰려면 `backend`의 `SecurityConfig.corsConfigurationSource()`에 추가해야 합니다.

## 알려진 한계 / 설계상 트레이드오프

포트폴리오 특성상 의도적으로 범위를 좁히거나, 실사용 전 보완이 필요하다고 판단한 지점을 투명하게 남겨둡니다.

- **비밀번호 재설정 이메일 미발송**: 재설정 링크를 실제 메일로 보내지 않고 서버 로그로만 남깁니다. 실사용 전 메일 발송 연동이 필요합니다.
- **SSE는 단일 서버 인스턴스 기준**: 활성 연결을 메모리에 보관하므로, 스케일아웃 시 다른 인스턴스에 붙은 클라이언트에게는 알림이 전달되지 않습니다. 필요 시 Redis Pub/Sub 등으로 인스턴스 간 브로드캐스트를 추가해야 합니다.
- **Access Token 즉시 무효화 불가**: 이메일 변경/계정 정지 시점에 이미 발급된 토큰은 stateless 구조상 최대 1시간 뒤 자연 만료됩니다.
- **리마인더 스케줄러의 단순 매칭**: 정확히 해당 날짜에만 매칭하는 방식이라, 그 시각에 서버가 꺼져 있으면 알림이 누락될 수 있고, 중복 방지 플래그가 없어 같은 날 여러 번 실행하면 중복 알림이 생성될 수 있습니다.
- **대기자 명단은 선착순 1명에게만 알림**: 스탬피드 방지를 위한 설계이며, 해당 유저가 확정하지 않아도 다음 순번에게 자동으로 넘어가지 않습니다.
- **예약 목록의 병원/시간 정보는 클라이언트 측 N+1 조합**: `Reservation` 응답 자체에 병원명/시간 필드가 없어, 프론트에서 병원 목록과 슬롯을 조회해 조합하는 방식입니다. 병원 수가 적은 포트폴리오 규모에서는 문제없지만, 규모가 커지면 백엔드 DTO에 필드를 추가하는 것이 맞습니다.
- **리뷰 작성자 식별의 한계**: `ReviewResponse`에 작성자 식별 필드가 없어, 프론트가 브라우저 로컬 스토리지로 "내가 쓴 리뷰"를 추적합니다. 다른 브라우저/기기에서는 수정·삭제 버튼이 보이지 않습니다.
- **급여량 계산기/자가문진은 참고용**: 활동계수 매핑과 자가문진 점수 기준은 공개 자료를 기반으로 추정/보간한 값이며, 실제 서비스 전 수의사 자문을 통한 재검증이 필요합니다. 품종/연령별 평균 통계 데이터는 허위로 만들지 않고 부재 사실을 그대로 안내합니다.
- **리뷰 숨김은 수동 처리**: 신고가 누적되어도 자동으로 숨겨지지 않고, 관리자가 직접 검토 후 숨김 처리하도록 설계했습니다.
