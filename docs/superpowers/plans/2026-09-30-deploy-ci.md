# 배포 + CI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** PetCare 모노레포를 EC2 1대에 Docker Compose(web=Caddy+프론트, backend, mysql)로 HTTPS 배포하고, GitHub Actions가 테스트 통과 시에만 자동 배포하게 한다.

**Architecture:** 브라우저는 `https://<DOMAIN>` 한 오리진만 호출하고 Caddy가 `/api`·`/uploads`·Swagger를 backend로, 나머지를 SPA 정적 파일로 보낸다. 이미지는 Actions에서 빌드해 GHCR에 올리고, EC2는 `pull && up -d --no-build`만 한다. 로컬에서도 같은 compose 파일을 `up --build`로 띄워 검증한다.

**Tech Stack:** Docker / Compose v2, Caddy 2, eclipse-temurin 21, node 24(slim), mysql 8, GitHub Actions, GHCR, AWS EC2(Ubuntu), DuckDNS

**Spec:** `docs/superpowers/specs/2026-09-30-deploy-ci-design.md`

## Global Constraints

- 이미지 이름은 소문자 고정: `ghcr.io/codevins/petcare-backend`, `ghcr.io/codevins/petcare-web` (`github.repository_owner`는 `CodeVins`라 대문자 → 쓰면 안 됨)
- 태그: `latest` + `sha-<커밋 SHA>`. compose는 `:${TAG:-latest}`
- 시간대: backend·mysql 모두 `Asia/Seoul` (backend는 JVM `-Duser.timezone=Asia/Seoul` + `TZ`)
- 메모리: JVM `-Xmx320m`, MySQL `--innodb-buffer-pool-size=128M --performance-schema=OFF`, EC2 swap 2GB
- 비밀값은 서버 `~/petcare/.env`에만. 레포에는 `.env.deploy.example`(키 목록만)
- mysql·backend 포트는 호스트에 publish 하지 않음. 공개 포트는 web의 80/443뿐
- 백엔드 CORS 설정은 건드리지 않음(같은 오리진이라 운영에서 불필요)
- 기존 코드 수정 시 `// 변경(2026-09-30): 무엇 — 왜 (이전: ...)` 주석(백엔드/프론트 CLAUDE.md 규칙). YAML은 `#`로 같은 형식
- 커밋 메시지: `타입: 설명` 한국어, 끝에 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`
- Node 24(로컬 v24.21과 일치), Java 21

## Review Focus

1. **Windows에서 만든 lockfile로 Linux `npm ci`** — oxlint·tailwind oxide·rolldown 네이티브 바이너리가 lockfile에 linux용으로 없으면 설치 실패. Task 3의 Docker 빌드(Linux)에서 먼저 드러나게 함 → 실패하면 `npm install --package-lock-only`로 lockfile 재생성 후 커밋
2. **MySQL 8 컨테이너 첫 접속 "Public Key Retrieval is not allowed"** — `DB_URL`에 `allowPublicKeyRetrieval=true&useSSL=false` 필수. Task 4 기동 로그로 확인
3. **HTTPS 프록시 뒤 Swagger "Try it out"이 `http://`로 요청해 혼합 콘텐츠 차단** — `server.forward-headers-strategy: framework`. Task 4에서 `/v3/api-docs`의 `servers[0].url`이 프록시 스킴을 따르는지 확인
4. **SSE가 프록시(Vite, Caddy)에서 버퍼링돼 알림이 안 옴** — Task 1(Vite)과 Task 4(Caddy)에서 `curl -N`으로 heartbeat(`:ping`, 25초) 수신 확인
5. **SPA 딥링크 새로고침 404 / 재시작 후 업로드 사진 소실 / UTC 시간대** — Task 4에서 `/mypage/reviews` 직접 요청 200, 업로드 → `docker compose restart` → 이미지 200, 컨테이너 `date`·JVM 시간대 확인

### Task 6: CD — 이미지 push + EC2 배포 + 가이드

**Files:**

**Interfaces:**

- [ ] **Step 1: `docs/DEPLOY.md` 작성 (사용자가 따라 할 1회 세팅)**

````markdown
# 배포 가이드 (EC2 + Docker Compose)

구조·결정 이유: `docs/superpowers/specs/2026-09-30-deploy-ci-design.md`

## 1. EC2 (1회)
1. EC2 → 인스턴스 시작: Ubuntu 24.04, t3.micro, 스토리지 20GB, 키페어는 **배포 전용**으로 새로 생성(`petcare-deploy.pem`)
2. 보안그룹 인바운드: 22(내 IP), 80(0.0.0.0/0), 443(0.0.0.0/0)
3. 탄력적 IP 할당 → 인스턴스에 연결 (퍼블릭 IPv4는 프리티어 12개월 750시간 포함, 이후 과금)
4. https://www.duckdns.org 로그인 → 서브도메인 생성 → current ip에 탄력적 IP 입력

## 2. 서버 준비 (1회, `ssh -i petcare-deploy.pem ubuntu@<IP>`)
```bash
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker ubuntu && exit   # 재접속해야 그룹 반영
sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
mkdir -p ~/petcare && nano ~/petcare/.env   # .env.deploy.example 키 전부 채우기
```

## 3. GitHub (1회)
- Settings → Secrets and variables → Actions: `EC2_HOST`(탄력적 IP), `EC2_USER`(`ubuntu`), `EC2_SSH_KEY`(pem 파일 내용 전체)
- 첫 main push 후 `build-push`가 끝나면: GitHub 프로필 → Packages → `petcare-backend`, `petcare-web` 각각 Package settings → Change visibility → **Public** (서버가 로그인 없이 pull)
- 그다음 실패한 `deploy` job을 Re-run

## 4. 평소 배포
main에 push(또는 PR 머지) → test 통과 시 자동 배포. 진행 상황은 Actions 탭

## 5. 운영 명령 (서버에서, `cd ~/petcare`)
- 로그: `docker compose logs -f backend`
- 상태/메모리: `docker compose ps`, `docker stats --no-stream`
- 롤백: `.env`에 `TAG=sha-<이전 커밋 SHA>` 추가 → `docker compose pull && docker compose up -d --no-build` (되돌릴 땐 `TAG=latest`)
- DB 접속: `docker compose exec mysql mysql -u petcare -p petcare`
````

- [ ] **Step 2: 워크플로에 `build-push`, `deploy` job 추가**

`.github/workflows/ci-cd.yml`의 `jobs:` 아래 `test` 뒤에 추가:

```yaml
  build-push:
    if: github.event_name == 'push'
    needs: test
    runs-on: ubuntu-latest
    permissions:
      contents: read
      packages: write
    strategy:
      matrix:
        include:
          - name: petcare-backend
            context: backend
          - name: petcare-web
            context: frontend
    steps:
      - uses: actions/checkout@v4
      - uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}
      - uses: docker/build-push-action@v6
        with:
          context: ${{ matrix.context }}
          push: true
          tags: |
            ghcr.io/codevins/${{ matrix.name }}:latest
            ghcr.io/codevins/${{ matrix.name }}:sha-${{ github.sha }}

  deploy:
    if: github.event_name == 'push'
    needs: build-push
    runs-on: ubuntu-latest
    concurrency: deploy
    steps:
      - uses: actions/checkout@v4
      - name: compose 파일 복사 후 pull/up
        env:
          KEY: ${{ secrets.EC2_SSH_KEY }}
          TARGET: ${{ secrets.EC2_USER }}@${{ secrets.EC2_HOST }}
        run: |
          mkdir -p ~/.ssh && echo "$KEY" > ~/.ssh/deploy && chmod 600 ~/.ssh/deploy
          OPTS="-i ~/.ssh/deploy -o StrictHostKeyChecking=accept-new"
          scp $OPTS docker-compose.yml "$TARGET:petcare/docker-compose.yml"
          ssh $OPTS "$TARGET" 'cd petcare && docker compose pull && docker compose up -d --no-build && docker image prune -f'
```
